**Цель:** изучить основы отзывчивой верстки (RWD), научиться адаптировать макет к различным размерам экранов, использовать медиа-запросы, контейнерные запросы и отдельные стили для печати.

## Изучить

Изучить основы адаптивной верстки:

- принцип mobile-first;
- создание и использование медиа-запросов и контейнерных запросов;
- синтаксис медиа-запросов с использованием операторов сравнения (>, <, >=, <=);
- типы устройств и характеристики;
- метатег viewport;
- шаблоны поведения адаптивного макета;

## Сделать

Применяя принцип mobile-first, сделайте страницу отзывчивой к отображению на экранах разной ширины: от 360px до 2560px.

Добавьте, где требуется (header, sections, footer) группирующую обертку в виде элемента `div` с классом `wrapper`. Пример его кода приведен ниже, но размеры в `max-width` и `padding` сверяйте с вашим макетом.

```css
.wrapper {
  max-width: 1170px;
  margin-left: auto;
  margin-right: auto;
  padding-left: 16px;
  padding-right: 16px;
}
```

Добавьте недостающие элементы в разметку html для настольной версии. Используйте для скрытия элементов на мобильной версии `display: none;`, чтобы потом с помощью медиа-запросов их отобразить.

Используйте минимум 2 точки перехода (breakpoint) в медиа-запросах с обоснованием их выбора. Помните что можно использовать возможности flexbox и grid.

Добейтесь адекватного перестроения макета при увеличении ширины экрана:

- не должна появляться горизонтальная полоса прокрутки;
- не должно быть неоправданно больших областей пустого пространства;
- не должно быть переполнения содержимого;
- элементы не должны накладываться друг на друга;
- текст и изображения должны корректно адаптироваться к доступному пространству.

На одном из элементов макета реализуйте адаптивное поведение с помощью контейнерного запроса @container. Для этого необходимо задать родительскому элементу контейнерный контекст с помощью container-type или container и изменить стили дочернего элемента в зависимости от ширины контейнера.

Подготовьте отдельную версию страницы для черно-белой печати. Стили печати должны подключаться отдельно с использованием `media="print"`.

В версии для печати:

- уберите фоновые изображения, цветные фоны и декоративные фоновые элементы;
- используйте белый фон и черный текст;
- скройте все элементы, которые не нужны на бумаге: навигацию, декоративные элементы, интерактивные элементы и т.п.;
- обеспечьте максимальную читаемость текста и контраст;
- отключите использование flex и grid для крупных структурных элементов там, где они мешают нормальному переносу содержимого между страницами;
- обеспечьте корректное расположение блоков и их перенос на следующие страницы;
- не допускайте обрезания содержимого по горизонтали;
- при необходимости измените размеры, отступы и другие параметры элементов.

Проверьте результат работы как минимум в следующих вариантах:

- мобильный экран;
- планшетный/промежуточный размер;
- широкий экран;
- режим печати/предпросмотра печати;

Зафиксируйте результаты работы с помощью системы контроля версий git и отправьте репозиторий на GitVerse.

## Требования к коду

1. Отсутствие ошибок на [валидаторе](https://validator.w3.org/) для html и css.
1. Код отформатирован и читаем.
1. Оптимально использован grid.
2. Использован принцип mobile-first.
3. Печатная версия страницы адаптирована для черно-белой печати.
4. Не допускается горизонтальная прокрутка или наложение элементов на контрольных размерах экрана и `overflow: hidden`.

## Результаты выполнения лабораторной работы

В результате выполнения лабораторной работы должна быть создана отзывчивая страница, корректно отображающаяся на экранах шириной от 360px до 2560px, а также отдельная версия страницы для черно-белой печати, зафиксированная в системе контроля версий Git и отправленная на GitVerse.
